Qualification passed. The actual server exposed all eight tools, returned both requested scratch symbols in one call, and returned the changed marker after a source edit. The current official release is CodeGraph 1.6.2 at commit `6560052a6f856855d3f71eee838fd66ccfa4285d`. The setup script verifies current GitHub and npm metadata again, then makes an independent APFS clone of the earlier pinned installation and checks every file and link against its retained inventory. It does not install into or execute the original runtime. The platform package supplies its own Node runtime and official launcher. [Release](https://github.com/colbymchenry/codegraph/releases/tag/v1.6.2), [pinned source](https://github.com/colbymchenry/codegraph/tree/6560052a6f856855d3f71eee838fd66ccfa4285d).

This control enables all eight supported retrieval tools through the official `CODEGRAPH_MCP_TOOLS` setting. The server retains its own guidance to begin with `codegraph_explore`, which accepts multiple symbol or file terms in one request. The seven narrower tools stay available. These are retrieval tools; ordinary native source editing and validation remain available to the coding agent. There is no claim that CodeGraph itself exposes an edit tool, arbitrary SQL, or a general array batch API. [Official MCP interface](https://raw.githubusercontent.com/colbymchenry/codegraph/v1.6.2/site/src/content/docs/reference/mcp-server.md).

The official CLI also offers `explore`, `node`, symbol query, callers, callees, impact, files and status. Its `affected` command follows import dependencies to tests. The launcher path is recorded in the arm; a caller can use it through native execution if the study exposes that capability. CodeGraph graph evidence is not itself owner specific TypeScript compiler proof, and neither syntax reachability nor an empty result establishes complete semantic impact. [Official CLI interface](https://raw.githubusercontent.com/colbymchenry/codegraph/v1.6.2/site/src/content/docs/reference/cli.md).

Each task gets a fresh external index and isolated home, config and cache. The only workspace state addition is `.codegraph`, a symlink to that run's external index. Setup charges the official initial index and status readiness checks. Codex starts the sole MCP client; any lazy daemon startup and subsequent refresh occur within its measured session. No model query is performed during provider setup. The native watcher stays enabled.

Cleanup checks the per-run nonce, workspace, state, daemon start time and exact runtime process identity before stopping it. The coordinating runner must additionally require Codex's process group cleanup. A reusable ready state is not shared across tasks. The small qualification runs exercise multi-symbol source retrieval, a real source edit followed by watcher refresh, and an actual Codex call returning an independent marker. These establish transport and freshness on scratch only, not task accuracy or an advantage in tokens or time.

These are scratch readiness measurements under concurrent research activity, not comparative latency results or estimates for a large repository. Lazy server startup is included in the agent session.
