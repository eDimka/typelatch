# Real maintenance agent trial

Availability study 002 completed sixteen sessions with native tools, Serena 2.1.0, the compact Typelatch 0.4.0 candidate and the source packet experiment. Every solution passed independent grading, but no session called MCP. Neither candidate met the savings gate. The complete public results and frozen protocol are in docs/benchmarks/monorepo-agent-study. Study 001 retains one completed native session and four tool launch failures caused by the recorder configuration; none is pooled into study 002. A fresh run requires a newly qualified spec and new output directory.

The primary tasks are pnpm project selection after a file move and an isolated real pnpm dependency API migration. Both use the full older monorepo source corpus and independent external graders. The migration explicitly upgrades one workspace dependency to the exact version and package closure in an upstream migration, then asks the agent to adapt the real consumer. Each task receives native tools, the compact Typelatch candidate with all seven optional tools, or the strongest qualified comparison tool. Two repeats yield12 sessions. An optional preregistered packet candidate produces16 sessions instead. Set `candidates` to `["typelatch","packet"]` and supply a fully frozen `arms.packet` launch configuration before protocol freeze. The schedule reverses the arm order for each task on its second repeat, uses task order ABBA, and balances every ordinal position exactly when four arms are included.

This task amendment occurred before any coding-model session. The initial pnpm plus date-fns template is retained under `pre-session-amendments/initial-datefns`. The primary question is the requested large monorepo and installed API workflow, so the genuine pnpm migration replaces date-fns here. The separately qualified date-fns case remains available for external replication. No actual coding-model task results informed the amendment.

Prompts are identical across arms. They request relevant source inspection and the same supplied native validation command before and after editing. Only the actual migration task asks the agent to adapt to the installed API. No task forces Typelatch adoption or MCP validation. Actual native check output and zero MCP use are recorded. A skipped requested check blocks a qualified win and is never silently removed. Multiple checks in one shell command are recognized by their separate public runner outputs; the command exit remains an aggregate value, while individual check exit codes remain unknown.

Each candidate is assessed separately against each control. The preregistered decision requires at least20% aggregate and median paired savings in both tokens and charged time against each control. Both repeat aggregates must improve. Correctness must not decline overall or per task, and each candidate must solve each task at least once. A `qualifiedWin` additionally requires all four candidate runs correct. Every capture, grade and requested native validation observation must finish, and every setup attempt is retained. Input totals include cached input; output is added once. A failed or interrupted preparation cannot be retried under the same protocol. `candidateDecisions` retains each independent result; `anyCandidatePassed` does not hide a losing standard candidate behind a winning packet candidate, and `anyQualifiedWin` distinguishes a complete correctness result from partial success. No candidate metrics are pooled.

Common full-corpus copying and independent grading are excluded from charged time. Provider preparation is included once, then agent wall time includes MCP startup, query/index work and native checks. Typelatch has no required package-index preparation. All per-run provider homes start fresh. OS file caches and hosted prompt caches may be warm. Teardown is separately recorded and must prove the owned provider processes stopped before another session starts.

Copy `spec.template.json` to a separate coordinator spec and fill the competitor selection and launch configuration. Server commands are absolute; `{workspace}` and `{state}` are substituted without a shell. Include every runtime/dependency closure in `frozenInputs`. A provider that creates a detached daemon must use `cleanupMode: "lifecycle"` and an external frozen `lifecycleModule` exporting `start({workspace,state,arm})`. It returns `{evidence,close}`, and `close()` returns `{stopped:true,...}` only after verifying its owned processes exited. If start can fail after spawning, export `cleanupFailedStart({workspace,state})` as well. Lifecycle startup is charged; its client may stay alive through the agent if required by the supported provider configuration.

Declared provider state inside a corpus may only be a `.codegraph`, `.serena` or `.graphify` symlink into that run's external state directory. All original fixture bytes and link targets must match before setup; setup cannot change them. The independent grader binds its protected manifest after approved state links are added. Provider indexes and truth/reference artifacts remain outside the coding corpus.

Each copied coding corpus receives its own Git root and one initial commit of the exact original source inventory. This prevents the ignored parent artifacts directory from hiding source. Committed fixture symlinks under ignored directories remain tracked, while installed dependencies remain untracked. The initial Git root and HEAD must survive grading. The pnpm native checks create separate temporary Git repositories and do not use this corpus history.

Commands, after offline tests and launch configuration are reviewed:

```sh
node artifacts/research/large-monorepo/agent-trial/run.mjs --freeze /absolute/coordinator-spec.json /absolute/new-study-directory
node artifacts/research/large-monorepo/agent-trial/run.mjs --run /absolute/coordinator-spec.json /absolute/new-study-directory
```

`--freeze` only inventories and verifies inputs; it runs no model task. `--resume` requires an unchanged protocol and completed prefix, with no interrupted preparation or live owned process. The exact candidate archive is bound to installed Typelatch package files. Fixtures, native grader dependencies, harnesses, tool runtimes and Codex binary are hashed. Private raw JSONL is retained with restricted permissions. Eligible public evidence contains only allowlisted actions, source changes, independent test output, usage and timing metadata. It contains no model reasoning or assistant message bodies. Review exports before publication.

One task tests an installed API migration and one tests a source workflow in the same pnpm snapshot. They are public maintenance changes and may occur in model training data. Two tasks with two repeats are a bounded decision, not universal superiority or a confidence interval. The earlier losses remain separate evidence. A win against native tools and the selected competitor does not establish superiority over another tool that has not yet faced the same coding tasks.
