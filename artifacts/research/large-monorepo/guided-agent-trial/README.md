# Guided retrieval follow up

Independent source review found no blocker, and all 21 offline checks passed. Actual Codex startup receipts were reused after verifying identical recorder bytes and complete arm configurations. The protocol is frozen at SHA256 `540a7abf0cc328323f39e7f99ff5c4fd032e02faa2d3bcee67ff39c9937a7a3f`. No guided model session has been launched. The coordinator must publish the protocol before launch.

This separate study asks whether a retrieval workflow helps when the agent is instructed to use it. It was proposed after the first task in availability study 002 completed with zero MCP use in all four conditions. Every earlier result remains retained and separate. This study cannot establish automatic adoption or erase an availability failure.

The same two qualified pnpm tasks, task descriptions, full corpus fixtures, independent graders, model configuration, native tools, frozen packet runtime and Serena runtime are reused unchanged. Native, Serena and packet each receive two repeats per task, giving twelve sessions. The task blocks use order ABBA, and each task reverses arm order in its second repeat. Three arms cannot occupy every ordinal position equally across four blocks. No candidate query template, implementation path or repair is supplied.

Every arm receives the same additional instruction:

> Run the supplied failing check before investigating the implementation. First investigation means a task-directed source or path search, source read, or targeted dependency/configuration inspection. Harmless working-directory checks, generic top-level project metadata, the supplied check itself, and required provider startup instructions are separate. For your first investigation, use a task-relevant repository discovery or source-inspection call through a connected repository retrieval provider when one is available; otherwise use the native tools. Read any provider startup instructions required to make that call. Then choose freely among the available tools, make the minimal repair, and run the same native check again.

The task runner is `npm run test:typelatch-benchmark` in every arm. Provider startup instructions do not count as source investigation. One task relevant retrieval attempt through `workspace_evidence` or `serena_repl` is required in the respective provider arms. The native control chooses its ordinary native investigation. No additional API query, provider validation, successful retrieval or sequence of follow up calls is forced. A failed relevant retrieval remains an attempted use with all its costs retained. Whether it returned usable source evidence is recorded separately.

The economic gate requires at least 20 percent savings against both native and Serena in total tokens and charged time, in both aggregate and the median of four task and repeat paired percentage reductions. Both repeat aggregates must improve on both metrics. All four packet runs must be correct, with no overall or per task correctness loss. Every capture, cleanup, grade and requested native validation observation must complete. No omitted attempts or replacement runs are allowed.

Every provider setup operation, startup instruction, retrieval, failure, fallback, query index build and native check is charged. Charged time is provider setup plus agent elapsed time. Shared corpus preparation, independent grading and teardown are recorded separately. Cached input remains in input tokens, and output is added once. Every arm starts with fresh provider state. Operating system and hosted prompt caches may be warm, as in the availability study.

The interpretation above is included in the frozen protocol as `workflowReviewRules`, as well as in the decision gate. It applies identically to all arms. Targeted source paths, dependency declarations and configuration reads count as investigation even when the command reads metadata; a generic top level directory listing or working directory check does not.

The replay pair is selected before guided outcomes: `pnpm-changed-project-move-r1-native` and `pnpm-changed-project-move-r1-packet`. The frozen protocol records it as `replaySelection`. Failed calls or repairs remain visible; no later pair is substituted. The replay uses actual action receipt timestamps and discloses any display speed compression.

An economic result cannot become a qualified workflow win until an independent reviewer checks the public actions for all twelve runs. The reviewer cites the first failing native check, first source investigation and provider retrieval action where required. The first relevant provider retrieval must follow the check and precede editing. A `serena_repl` call that only lists memories or tools does not qualify. Relevance, source investigation and command internal ordering require human judgment; if the public command or edit evidence cannot establish the sequence, mark it unknown. Do not infer compliance from total MCP counts.

The review is bound by hashes to the final private report, frozen protocol and every public evidence file. It does not read raw JSONL, private reasoning or assistant message bodies. Automatic checks verify cited action IDs, expected server and tool, visible action ordering and immutable evidence. They cannot independently prove a human relevance judgment or every edit hidden in shell commands. Unknown or failed compliance prevents a qualified win and remains in the report.

`run.mjs` retains the same interrupted preparation and cleanup safeguards as the availability harness. `capture.mjs` is an exact copy of its corrected environment leaf serialization. Only the guided prompt, fixed three arm selection, decision requirement and later manual review differ. The original harness and runtime are untouched.
